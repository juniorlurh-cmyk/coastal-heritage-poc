# Coastal Heritage — Website Concept

A multi-page marketing website for Coastal Heritage, a construction and property
services business listed in Sunnyside, Pretoria. Built as a prospecting
prototype — not yet an approved or production-ready company website.

## Structure

```
├── web/                    React + Vite application (the website)
│   ├── src/
│   │   ├── components/     Layout, nav, footer, cards, forms, chat, slideshow
│   │   ├── pages/          Home, About, Services, Projects, Contact, Insights, 404
│   │   ├── data/           Site details, services, projects, ratings, areas, market
│   │   ├── ai/             AI provider layer (Groq free tier + keyless fallback)
│   │   └── styles/         Global design system (single stylesheet)
│   └── index.html          Entry + SEO meta + LocalBusiness JSON-LD
├── deploy/                 Deployment docs
│   └── DEPLOYMENT.md       GitHub Pages setup, free domain, analytics, go-live checklist
├── docs/
│   ├── ARCHITECTURE.md     Full project documentation — stack, structure, decisions
│   └── AI.md               AI assistant + market briefing: free key setup, security
├── .github/workflows/
│   └── deploy.yml          Builds web/ and publishes to GitHub Pages on push to main
├── legacy/                 Original single-file static prototype (reference)
├── EVALUATION.md           Competitor benchmark, rubric, self-critique
├── PROSPECT_NOTES.md       First-call positioning and discovery questions
└── *_template.csv          Blank registers for verified projects/reviews
```

## Run locally

```bash
cd web
npm install
npm run dev        # http://localhost:5173
npm run build      # production build → web/dist/
npm run preview    # serve the build locally
```

Routing is handled by React Router (`/`, `/about`, `/services`, `/projects`,
`/contact`, `/insights`). On GitHub Pages a `404.html` copy of `index.html` (generated by
`postbuild`) provides the SPA fallback, and `basename` is set from
`VITE_BASE` so the site works under `/<repo>/` project-page paths.

## What is included

- Six real pages with client-side routing and a mobile menu.
- Dark utility topbar (phone, hours, area) and WhatsApp-first contact paths.
- Service detail sections with per-service quote links (`/contact?service=…`).
- Auto-advancing services slideshow on the home page.
- Filterable project portfolio (representative Pretoria case studies).
- "Where we work" gallery: **real photographs** of the actual suburbs
  (Wikimedia Commons, CC-licensed, credited) — no generic renders.
- **AI assistant** (floating chat) — answers service/area/quote questions via
  a free Groq key, with a rule-based fallback when no key is set. See
  `docs/AI.md`.
- **Market insights page** (`/insights`) — modelled demand matrix per suburb
  and trade for the internal team, plus an AI-generated market briefing.
- Reputation dashboard showing each rating source separately — Google 5.0
  (1 review) and Cybo 4.8 (4 reviews) are never blended.
- Enquiry form that composes a WhatsApp message; nothing is stored server-side.
- Optional Umami analytics (cloud free tier) — enabled only when
  `VITE_UMAMI_URL` and `VITE_UMAMI_WEBSITE_ID` are set at build time.
- `noindex` protection and a single footer note flagging preview-stage content.

## Deploy

Hosted on **GitHub Pages** — free hosting, free HTTPS, free `github.io` domain.
Enable via repo → **Settings → Pages → Source: GitHub Actions**, then push to
`main`. Live at `https://juniorlurh-cmyk.github.io/coastal-heritage-poc/`.
Details in `deploy/DEPLOYMENT.md`.

## Still required before publication

trading name, address (220 Robert Sobukwe St vs 89 Vos St conflict), real
services and credentials, real project photos, owner-approved copy, and the
actual review profiles. Project photos, case-study details, email and hours on
